GCC 0.30.0 adds proof-carrying bounded revision-impact analysis for firmware and RTL research workflows.

## Release highlights

- **Revision-impact certificates:** Check whether a source change invalidates evidence or changes a bounded result.
- **Strict interfaces:** Use bounded Rust, file CLI and typed subprocess APIs with no-fallback verification and work telemetry.
- **Connected evaluation:** Reproduce 20 OpenTitan PWM observations, including a combination-only regression.
- **External agreement:** Match maintained Yosys, rIC3 and Certifaiger evidence across 9 SAFE and 11 UNSAFE observations.
- **Release hardening:** Reproduce the public artifact and reject nine hostile-drift cases in a hosted Linux build.
- **Stable integration:** Add a crates.io-backed API compatibility gate and adopt QatQ 0.1.4's exact-byte container API.

## Measured result

| Measure | Result |
| --- | ---: |
| Source-to-answer time | 53.78x faster |
| Producer-path peak memory | 20.0% lower |
| Artifact size | 8.32x larger |

These figures compare one shared GCC workflow with 20 isolated maintained-tool jobs on the matched OpenTitan cohort.
They are not a universal solver-performance claim.

## Install

Complete research build:

```sh
cargo install guarded-continuation-checker --version 0.30.0 --locked
```

Frozen firmware and RTL profile:

```sh
cargo install guarded-continuation-checker --version 0.30.0 --locked \
  --features production-firmware
guarded-continuation-checker production-profile-version
```

The reported production-profile capability remains:

```text
production_support_profile=firmware-rtl-v1 firmware_cli_version=2 artifact_schema_version=4
```

Revision impact and QatQ transport are research surfaces. They are not included in `firmware-rtl-v1`.

## Status and scope

GCC is an evaluation-ready research prototype, not a production-qualified or certified verification product.

This release demonstrates a narrow source-bound certificate and self-service workflow. It does not claim a proven novel algorithm.
